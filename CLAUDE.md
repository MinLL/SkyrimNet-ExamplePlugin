# CLAUDE.md

This repo holds example SkyrimNet plugins that mod authors copy to build their own. Code here is
read as the reference for "how to do it right", so it must be clean, commented for a first-time
reader, and free of shortcuts.

## Start here

| The author wants | Start from |
|---|---|
| NPC actions, events, a version check, in Papyrus | `examples/01-papyrus-basics` |
| Their mod's data in NPC prompts, a custom event type | `examples/02-papyrus-context` |
| C++ decorators or actions, memory queries | `examples/03-cpp-native` |

Rules with reasons: `docs/best-practices.md`. Content formats (actions, triggers, prompts, roots):
`docs/modding/`. The API itself: `sdk/cpp/PublicAPI.h`, `sdk/papyrus/SkyrimNetApi.psc`.

## Commands

```powershell
./scripts/fetch-tools.ps1         # once: Papyrus compiler, Spriggit
./build.ps1                       # examples 01, 02
./build.ps1 -Preset full          # all three (VS 2022 + VCPKG_ROOT)
./scripts/spriggit-sync.ps1 <esp> # after editing an .esp in xEdit/CK
external-tools/skyrimnet/content-validate.exe <layer dir>   # validate a layer
```

From the Bash tool, run these through `powershell.exe -ExecutionPolicy Bypass -File <script>`.

## Hard rules

- No Papyrus `RegisterAction`, `RegisterSubCategory` or `RegisterDecorator`: they are deprecated.
  Actions and categories are YAML; decorators are `papyrus_util` or C++.
- Check SkyrimNet before calling it: `SKSE.GetPluginVersion` + `GetBuildVersion` in Papyrus, resolved
  pointers in C++. Keep the manifest's `min_skyrimnet_version` in step.
- Nothing slow on the game thread. C++ action `execute` runs there; queries and I/O go to a worker.
- In C++, only `SkyrimNetBridge.cpp` includes `PublicAPI.h` (it defines globals).
- One prefix for everything a mod owns: scripts, editor ids, StorageUtil keys, decorators, event types.
  Action names are LLM-facing plain words.
- Content goes in the external layer. Folder name = manifest `id`; `author` = the id's author segment;
  `.yaml` and `.prompt` only (case-sensitive), ASCII paths; action file name = its `name`.
- Prompts: add numbered submodule files, never replace SkyrimNet's. `character_bio` files test
  `render_mode` within 5 lines. Calls to a mod's own C++ decorators stay out of `character_bio`.
- `sdk/` is generated by SkyrimNet's release CI. Never edit it.
- Form ids you hardcode or put in Spriggit must be verified against the real master file.

## Before you finish

1. `./build.ps1` (and `-Preset full` if C++ changed) succeeds with no warnings.
2. `content-validate` reports 0 errors for every layer you touched. Unresolved game variables are
   expected offline.
3. If the game is running with SkyrimNet, use the `skyrimnet` MCP server (`.mcp.json`):
   `get_decorators` to confirm a decorator exists in this build, `validate_custom_action`,
   `validate_prompt`, and `render_template` against a real NPC. Without the game, say what was not
   checked.
4. Update the example's README and `docs/` if behavior they describe changed.
